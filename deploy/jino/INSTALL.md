# ELSTAR — приём заявок в Джино

Статус: файлы обработки и проверки установлены владельцем; подключение к базе и таблицы проверены.
Оформление на витрине остаётся через менеджера. Не включать обработчик до подключения
проверки корзины, личного кабинета и документов по обработке данных.

## Первый шаг

Загрузить только `public/elstar-ready.php` через файловый менеджер Джино в
`domains/3d2ef918ae94.hosting.myjino.ru/`. Открыть
`https://3d2ef918ae94.hosting.myjino.ru/elstar-ready.php`.
Первые шесть строк проверяют PHP и расширения; следующие строки пока могут показывать
«Нужно настроить». Проверка ничего не записывает и не отправляет в Telegram.

## Установка после проверки

1. В корне аккаунта (рядом с `domains`, `logs`, `tmp`) создать папку `elstar-private`.
2. В неё загрузить `private/requests.php`; скопировать `private/config.example.php`
   под именем `config.php`. Вставить пароль пользователя `j60934287_orders` локально
   в файловом редакторе Джино. Не отправлять пароль в чат. `enabled` оставить `false`.
3. Через управление MySQL импортировать `private/schema.sql` в базу `j60934287`.
   У пользователя `j60934287_orders` должны быть права чтения/записи в этой базе.
4. Загрузить `public/elstar-requests.php` рядом с `elstar-ready.php`.
5. Проверить страницу готовности повторно. Персональные данные, конфигурация и фото
   находятся вне папки сайта; не перемещать `elstar-private` в `domains`.

## Подключение витрины — отдельный следующий шаг

Сервер витрины выдаёт через `/api/request-ticket` подписанный билет корзины без ФИО, телефона, почты,
адреса, комментария и фото. Браузер затем отправляет эти данные прямо в Джино.
В билет входят `v:1`, `aud` (origin витрины), `requestId` (UUID v4), `expires`
(Unix seconds, срок 5 минут), `kind`, `service`, `delivery`, `installation`,
`items` (проверенные id/sku/name/price/quantity), `total`, `prepayment`.
`ticket` — JSON UTF-8 в base64url без padding. `signature` — RSA-SHA256 подпись
точной строки `ticket`, также base64url. Закрытый RSA-ключ хранится только на сервере
витрины. В Джино передаётся публичный PEM в `ticket_public_key`. Загрузить `private/ticket-key.php`
в `elstar-private`, затем в существующем `config.php` заменить только строку ключа:
`'ticket_public_key' => require __DIR__ . '/ticket-key.php',`
Не заменять весь config.php: он содержит сохранённый владельцем пароль базы.
Серверный секрет `REQUEST_TICKET_PRIVATE_KEY` хранится в Sites и не включается в исходники.

POST — multipart/form-data: `ticket`, `signature`, `payload` (JSON с полями клиента,
kind,requestId,consent:true), `photos[]` (до 3 фото JPG/PNG/WebP по 5 МБ).
Чужие origin и неподписанные заявки отклоняются. Цены берутся только из билета.
Повтор того же номера и данных возвращает сохранённую заявку без дубликата.
Повтор с изменёнными данными возвращает 409. Заказ не считается резервом остатков.

## Личный кабинет

Подготовлены `private/admin.php` и `public/elstar-admin.php`. Их нужно установить
и проверить на Джино. Кабинет работает с существующими таблицами; повторный импорт не нужен.

1. Скачать `create-admin-password.html` и открыть локально в браузере на своём компьютере.
2. Задать отдельный пароль (минимум 12 символов), повторить его и скачать созданный
   `admin-password.php`. Страница не делает сетевых запросов. В файл записываются
   случайная соль и PBKDF2-SHA256 хеш с 600000 итераций; пароль в файл не записывается.
3. Загрузить `admin-password.php` и `private/admin.php` в закрытую папку `elstar-private`.
4. Загрузить `public/elstar-admin.php` в папку технического сайта рядом с обработчиком.
5. Открыть `https://3d2ef918ae94.hosting.myjino.ru/elstar-admin.php` и войти своим паролем.

Доступен один владелец: список/поиск по телефону или номеру, фильтр статуса,
статус заявки, оплата, личная заметка, контакты, товары и фотографии. Все действия
и фото требуют действующей сессии. Cookie — Secure/HttpOnly/SameSite=Strict;
сессия истекает после 30 минут бездействия или через 8 часов после входа.
Формы защищены CSRF-токеном и проверкой origin; ограничение — 5 попыток входа
за 10 минут с одного адреса. При замене файла пароля прежние сессии перестают работать.
Проверка синтаксиса PHP и полноценного входа/изменения заявок должна быть выполнена
на Джино перед включением клиентских форм: PHP в локальной среде отсутствует.

Для смены пароля повторить создание файла локально и заменить только `admin-password.php`.
Не отправлять файл пароля, сам пароль или конфигурацию с паролями в чат и не коммитить
их в репозиторий. Новый пароль базы должен быть изменён владельцем: прежний был виден
на скриншотах. Связь с Telegram на Джино ограничена провайдером (ответ поддержки 01.10.2026).
Telegram получает только номер и тип заявки. Подробности и фото хранятся в Джино.
Сбой уведомления не отменяет заказ. Когда токен/чат подключены, в кабинете доступен
повтор уведомления, завершившегося ошибкой; прочие уведомления повторно не отправляются.

Перед включением: выполнить проверку на Джино, подключить билет корзины, проверить
изменение цены/наличия и повторы, добавить документы/согласие, проверить кабинет
и доступ к фото. RequestForm нужно перевести на проверку `/api/request-ticket`
и прямую отправку данных/фото в Джино. Старый `/api/requests` должен остаться выключенным,
чтобы изменение флага формы не включило прежнее хранение клиентских данных.
После проверки нового потока поставить `enabled => true` и включить форму на витрине.
Удалить `elstar-ready.php`, `elstar-check.php`, `elstar-network-check.php`.
Пароли и закрытые ключи не входят в архив проекта; резервную копию БД хранить отдельно.

## Проверка подключения после установки кабинета

Вход, выход и повторный вход владельца подтверждены 1 октября 2026 года.
Исправлены Referrer-Policy для отправки формы и обработка отсутствующих q/status.

Клиентский submitJinoRequest сначала передаёт только состав корзины в /api/request-ticket,
затем отправляет контакты и photos[] непосредственно на Jino с credentials: omit.
Старый /api/requests остаётся закрытым отдельным legacyRequestsEnabled=false.
Формы покупателей по-прежнему закрыты onlineRequestsEnabled=false.

Для проверки владелец включает enabled в приватном config.php и открывает
/check-connection на опубликованном сайте. Страница отправляет только фиксированные
вымышленные данные; повторная кнопка использует тот же UUID. Проверить одну запись
в кабинете, затем статус, заметку, выход и закрытый доступ.
Эта проверка не подтверждает заказ с товарами, фотографии или Telegram.
Перед открытием клиентских форм ещё нужны проверка заказа/фото, политика и согласие,
а также смена ранее показанного на скриншотах пароля базы данных.

## Согласие перед включением покупателей

Опубликованы отдельные /privacy и /consent (версия 2026-10-02). Флажок не отмечен
по умолчанию; submit блокируется без согласия. Формы пока закрыты глобальным флагом.
Обновлённый клиент передаёт consentVersion непосредственно в Jino. Заменить
elstar-private/requests.php обновлённым файлом: сервер проверяет true и версию
согласия и сохраняет consent_version внутри payload вместе с временем создания.
Старые тестовые заявки не переписываются. Для повторного теста обновить страницу
/check-connection, чтобы использовать новый UUID.

После загрузки проверить новый тестовый заказ и отдельный звонок. Только после
смены ранее раскрытого DB-пароля одновременно в MySQL и приватном config.php,
проверки входа и согласия можно переключить onlineRequestsEnabled.
